# vultr-proxy-switcher 系统需求与设计文档

> 切 IP 代理系统（服务端 + 客户端 + Worker + 软路由）。本文档是唯一权威需求说明，记录**功能、业务规则、数据模型、关键决策和已知坑**。代码是「怎么实现的」，本文档是「为什么这么实现」。

---

## 1. 项目概述

### 1.1 是什么

给 TikTok 客户提供**海外 IP**（上游为 webshare 代理池）的切 IP 系统。客户连接固定域名（如 `xxx.yduas.cc`），切换 IP 时**无需改任何配置**，域名自动指向新 IP。

### 1.2 核心卖点

客户设一次域名后，切换 IP 不动配置。域名 TTL 短 + 客户端多 DNS 投票解析，绕过公共 DNS 缓存旧值。

### 1.3 目标用户

- **阿文（IP 代理商）**：卖海外 IP 给 TikTok 客户，打包路由器 + 线路按月收费。
- **TikTok 客户**：需要静态住宅 IP 专享（共享 IP 封号）。

### 1.4 上游账号（webshare）

| 账号 | IP 数 | 类型 | 备注 |
|---|---|---|---|
| gonglidanmm | 100 机房 + 3 静态住宅(isp) | shared + isp | 增值服务=3 个住宅 IP（身份真实，非提速） |
| baoyexiong4980 | 100 机房 | shared | 纯机房 |

## 2. 系统架构

```
客户端(Vue3+WebSocket) ──> Worker(Cloudflare) ──> 控制机(IPv6) ──> Vultr/Cloudflare 服务器 ──> webshare IP
                                        │
                                      D1(数据库)
```

| 组件 | 目录 | 技术 | 职责 |
|---|---|---|---|
| 服务端 | `app/` | PySide6 桌面 App | 管理界面：用户/节点/服务器/webshare |
| 客户端 | `client/` | Vue3 + WebSocket | 用户看节点、切 IP、扫码 |
| Worker | `worker/` | Cloudflare Worker + D1 | 鉴权、节点下发、流量同步、到期/用尽判定、切换 |
| 软路由 | 客户侧 | OpenWrt | 客户设备，连域名自动走代理 |

### 2.1 关键链路

- **切换链路**：客户端 → Worker → 控制机(IPv6) → Vultr/Cloudflare。
- **证书**：acme.sh 签通配符 `*.yduas.cc`（CF DNS-01），缓存复用未过期跳过 issue 防 LE 限流。
- **前端发布**：改 `client/src` 后 `npm run build` → `cp client/dist/{index.html,main.js,style.css} worker/assets/` → `cd worker && npx wrangler deploy --config wrangler.toml`。客户端加载远程 `https://user.yduas.cc/`，每 60s 查 `/build-stamp` 热更新。

## 3. 功能需求

### 3.1 用户管理

- 增删改用户、用户状态、订阅到期。
- **线路明细**：每用户的多条线路（独立/合并），显示出口 IP、上游账号、流量、到期、操作列。
- **线路明细内流量/到期只读展示**，修改统一在「管理 IP」弹窗。

### 3.2 中转节点（webshare IP）

- 中转生成：从 webshare 账号池选 IP，生成 relay（gost + sing-box 双栈）。
- **独立线路**：1 条线路 1 个 IP。
- **合并线路**：1 条线路多个 IP（候选轮换），候选上游收进 `candidates`，保留主 relay 参数。
- **分配用户**：把中转线路分配给用户，设置配额/到期（每 IP 可独立设置，顶部统一值改动即同步所有行）。
- **替换 IP**：同国家替换（州/城市随机），支持跨账号选择；实时回显（提交→轮询→completed/failed+error_code）。
- **回收 IP**：手动回收才进回收页（见 §4.6）。

### 3.3 服务器管理

- Vultr/Cloudflare 服务器 + 手工添加的服务器（inter-la-01、zenix-e01）。
- 服务器到期时间（compute_billing 算 days_left 动态写回）。

### 3.4 客户端

- 登录、节点列表、切 IP、二维码、复制节点/协议链接、订阅。
- 节点显示：生效配额（effQuota）、已用（effUsed）、生效到期（eff_expiry）。

### 3.5 回收管理

- 回收页展示已回收 IP，可「回归」解除冷却，IP 回未中转列表。

## 4. 核心业务规则（踩坑最多，务必精读）

### 4.1 配额（三处同步，缺一不可）

配额存**三个地方**，必须一致：

| 存储位置 | 字段 | 谁读它 |
|---|---|---|
| 分配记录 | D1 `assignments.quota_gb` | **客户端 / 外面线路明细（权威值）** |
| 节点快照 | `node_data.quota_gb` | 客户端 effQuota 兜底 |
| 候选 IP | `candidates[].quota_gb` | **Worker syncCandidateIpStatus 判定用尽** |

**规则**：
- 改配额永远允许任意值（1GB/0.5GB/20GB），**不限制「必须大于之前流量」**。
- 改配额/到期 = 续费动作（见 §4.5）。
- 保存时三处一起同步，否则出现「设 5GB 变 10GB」「超限不禁用」。

### 4.2 到期时间（三个字段）

| 字段 | 含义 | 谁读 |
|---|---|---|
| `node_data.client_expiry` | **独立线路的权威到期** | 外面线路明细 / 客户端 |
| `node_data.expiry` | 服务器级到期 | Worker 到期判定 |
| `candidates[].expiry` | IP 级到期 | Worker 判到期（合并线路读它） |

**规则**：
- 独立线路到期权威字段是 `client_expiry`。
- 合并线路（多候选）读候选 `expiry`。
- Worker 到期判定：候选 `expiry` 为空时回退 `client_expiry`，取更早者。
- 「还剩 X 小时」是**倒计时显示**（从分配时刻起算），不是「设置的时长被缩短」。

### 4.3 流量计量

- **双向 in + out**（转发架构使客户上传也成服务器出站成本，双向才对齐真实成本）。
- 服务器端 iptables 按 relay 端口计数，不依赖客户端。
- 流量显示 = `used_gb + hist_gb`（`hist_gb` = 切换时封账的 old_used_gb 累计，`listAllAssignments` 必须返回 hist_gb 否则少算）。

### 4.4 到期/用尽 → 自动禁用（绝不自动回收）

用户拍板铁律：

> 到期后自动禁用，不要回收。服务端可重新改到期/流量，或替换/加 IP 变合并即可继续用；只有**手动点击回收/删除**才进回收页。

- Worker cron（`* * * * *`）：`syncRelayTraffic`（同步流量）→ `syncCandidateIpStatus`（判到期/用尽 → `enabled=false` 标红；**所有候选禁用后调 `/stop` 真停服务器服务**）。
- 已删 `recycleExpiredRelays`（不自动回收）。
- **用尽判定**：`生效配额 = 候选 quota_gb || 分配记录 quota_gb`，`used >= 配额` 即用尽。

### 4.5 续费 = 清零重算

改配额/到期 = 续费动作，语义：

- `used_gb = 0`（封账流量清零）+ `reset_flow`（清分配记录 used_gb + 切换历史）。
- 到期未过期即 `enabled=true`。
- 重新部署服务器服务（服务可能之前被 `/stop` 停了）。
- **任意值均可**（含变小），不按「配额 > 已用」判断。
- 触发条件：保存前是禁用的候选，或本次会话点了「续费」按钮。

**「续费」按钮**（管理 IP 弹窗每 IP 一行）：不清零不禁用也能主动续费（填配额 + 到期 → 清零重算 + 启用）。「禁用/启用」只切状态不动流量，两者分开。

### 4.6 回收 = 停服务 + 流量审计

- 手动回收：删 D1 分配 + SSH 停服务（gost + sing-box）+ 记 `recycle_flow_log`（resource_id/username/name/host/ws_account/used_gb/hist_gb/reason）+ 进回收页。
- **回收必须真正停掉服务器服务**，否则代理继续烧流量。
- 停服务要反查 server_id → 用对应服务器密码 SSH，`systemctl disable --now` + 校验 `is-active`。

### 4.7 切换 IP

- **替换**：同国家（country_code），州/城市随机，v3 API；排除被替换 IP 本身；支持跨账号选择。
- **轮换**：relay 候选顺序轮换，跳过禁用/到期/用尽；relay 切换**不设次数上限**（仅 Vultr 销毁重建限 5 次/天）。
- 切换封账：当前 relay 累计流量记到旧 IP，新 IP 从 0 开始（每 IP 独立流量）。

## 5. 数据模型

### 5.1 D1 表（`vultr-proxy-users`）

| 表 | 关键字段 |
|---|---|
| `users` | id, username, password_hash, status, expires_at, switch_limit |
| `sessions` | token, user_id, expires_at |
| `assignments` | user_id, resource_type(vultr/relay), resource_id, node_data(JSON), quota_gb, used_gb, switch_count, switch_limit, switch_date, note, sort_order |
| `switch_requests` | old_id, new_id, old_used_gb, status, actor_type |
| `recycle_flow_log` | resource_id, username, name, host, ws_account, used_gb, hist_gb, reason, created_at |
| `certificates` | domain, fullchain, key, issued_at, expires_at |

- relay 专享：1 IP = 1 用户（`idx_relay_exclusive` 部分唯一索引兜底防并发）。
- `node_data._creds` 结构：`{ candidates:[{host,port,user,password,ws_account,quota_gb,expiry,enabled,used_gb}], active_idx, upstream, switch:{server_ip,port,api_key}, relay_id }`。

### 5.2 config.json（`~/.vultr-proxy-switcher/config.json`）

| 键 | 内容 |
|---|---|
| `relays` | 每条含 `candidate_upstreams`（候选，含 ws_account/quota/expiry/enabled）、`server_id`、`host/port/user/password` |
| `recycled_relays` | 已回收（含 ws_account） |
| `webshare_accounts` | 各账号 api_key |
| `manual_servers` | inter-la-01 / zenix-e01（id/host/user/password） |
| `user_lines_col_widths` 等 | UI 列宽持久化 |

## 6. 关键决策记录（ADR）

### ADR-001 webshare 多账号 → IP 级归属

数据从「线路级 ws_account」下沉到「每个候选 IP 记 ws_account」。原因：合并线路可能跨账号（如达拉斯-09 主 gonglidanmm + 候选 baoyexiong4980），线路级字段无法表达「哪个 IP 属于哪个账号」。替换/添加按当前 IP 反查账号池（`key_for_host`）。旧 relay 无 ws_account 显示第一个账号名（`default_account_name`）。

### ADR-002 到期/用尽自动禁用，不自动回收

用户拍板（原话见 §4.4）。删掉 `recycleExpiredRelays`，只自动禁用；只有手动回收才进回收页。

### ADR-003 改配额/到期 = 续费清零重算

用户原话「不能限制用户必须是多少流量，有时只需要 1GB，不能限制必须大于之前流量」。改为：改配额/到期任意值 → 封账清零 + reset_flow + 启用 + 部署。不按「配额 > 已用」判断。

### ADR-004 跨账号替换用 TDD

纯函数先行（`app/relay_ops.py` + `tests/test_relay_ops.py`，`uv run --with pytest`），`_IpPickerDialog` 加跨账号下拉。

### ADR-005 双向流量计量

in+out 双向（转发架构客户上传也是服务器出站成本）。

### ADR-006 替换/添加部署策略

仅 IP 集合变化才重新部署服务器；改配额/到期/禁用不部署（改到期/续费除外，见 §4.5）。

## 7. 已知坑（gotchas）

1. **候选 quota/expiry/server_id 没同步**：分配/改配额时只写了分配记录，候选是 0/空 → 「超限不禁用」「到期不判」「回收停服务用错密码」。**分配时必须同步候选三字段**，Worker 判定要回退到分配记录值。
2. **server_id 空 → 回收停服务失败**：`_ssh_stop_relay` 读不到 manual 服务器密码，用了旧的 root_password，SSH 认证失败，服务没停继续烧流量。已加 `_resolve_server_conn` 从 config.relays 反查兜底。
3. **gost 端口冲突竞态**：部署时旧进程没退出干净，`bind: address already in use`，systemd 重启数次后自愈。部署后稍等再测。
4. **续费改配额 QSpinBox 未同步**：`_renew` 改内存值但表格框没更新，点保存时 `_collect` 用表格旧值覆盖 → 「5GB 变 10GB」。
5. **`speedtest.tele2.net` 不适合测速**（国内直连都超时），测速用 `speed.cloudflare.com`。
6. **WKWebView 缓存**：清法先 `pkill -9` 停进程 → `rm -rf ~/Library/WebKit/proxy-client ~/Library/Caches/proxy-client` → 重启。
7. **wrangler deploy 目录**：必须在 `worker/` 下 `npx wrangler deploy --config wrangler.toml`（根目录会失败）。
8. **服务器国际带宽**：zenix-e01 实测仅 7.16 Mbps（inter-la-01 是 144 Mbps），大量线路挤 zenix 会整体卡。webshare 数据中心 IP 实测 1.8 Mbps，是「卡」的次级瓶颈（换服务器解决不了这一段）。
